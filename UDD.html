1. 프로젝트 개요

WarrenBuffett Bot은 개인 투자자(개미) 과열 신호를 역이용하는 역발상(Contrarian) 자동매매 시스템입니다. 매일 16:10 KST에 pykrx로 당일 데이터를 수집하고, Claude API 기반 4개 에이전트 합의 게이트를 통과한 종목만 매수합니다. Railway PostgreSQL에 모든 상태를 저장하며 FastAPI 웹 대시보드로 포지션·거래내역을 관리합니다.

최대 포지션 수

12
SLOTS — DB 설정으로 런타임 변경 가능

진입 Heat 임계값

< 7.0
HEAT_AVOID — 낮을수록 보수적 진입

청산 Heat 임계값

≥ 8.5
HEAT_SELL — 과열 구간 도달 시 청산

최대 보유 기간

20일
MAX_HOLD_DAYS

손절 기준

-7%
STOP_PCT

AI 모델

Sonnet 4.6
에이전트당 최대 256 토큰 응답
핵심 혁신 4개 에이전트 합의 게이트: market_state·risk는 거부권(veto)을 보유하고, retail_flow·credit_heat는 2/2 합의 투표를 담당합니다. 어느 한 veto 에이전트가 "관망" 또는 "청산"을 리턴하면 즉시 매수 거부됩니다.

3. 일일 실행 흐름

APScheduler가 평일 16:10 KST에 daily_job()을 트리거합니다.

1
collect_daily() — pykrx → stock_daily 테이블 증분 upsert
2
collect_flow() — pykrx 투자자별 순매수 → investor_flow
3
collect_kis() — KIS OpenAPI 신용잔고 일별추이 수집 → credit_balance
4
compute_for_date() — 전 종목 heat_score 계산 → contrarian_signals
5
get_exit_candidates() → sell() — stop / expiry / heat_signal 해당 포지션 청산
6
get_entry_candidates() → gate.decide() → buy()
heat < 7.0 & 52주 하위 30% 종목 필터 → 4에이전트 합의 통과 시 모의 매수
7
summary() — 거래 통계 로그 출력

에이전트 게이트 내부 흐름

gate.decide(code, date)
  │
  ├─ market_state.analyze()  → decision: 매수 | 관망 | 청산
  │     ↳ fall_pct ≥ 70% 이면 하드코딩 "청산" (VETO)
  │
  ├─ risk.analyze()          → decision: 매수 | 관망
  │     ↳ free_slots = 0    → 하드코딩 "관망" (VETO)
  │     ↳ same_sector ≥ 3  → 하드코딩 "관망" (VETO)
  │
  ├─ retail_flow.analyze()   → decision: 매수 | 관망  (vote)
  │
  └─ credit_heat.analyze()   → decision: 매수 | 관망  (vote)

결과:
  veto 에이전트 중 하나라도 관망/청산 → approved = False
  retail_flow + credit_heat 중 "매수" < 2 → approved = False
  모두 통과 → approved = True → paper.buy() 호출

7. Collector 모듈 collector/

stock_daily.py

FinanceDataReader로 KRX 전 종목 코드를 가져온 뒤, collect_cursor를 기준으로 마지막 수집일 이후 데이터만 pykrx에서 증분 수집합니다. 요청 간 0.35초 딜레이(KRX 쓰로틀링 방지).

investor_flow.py 2026-08-10 버그 수정

stock_daily의 종목 목록을 기준으로 pykrx.get_market_trading_value_by_date(start, end, code, on="순매수")를 호출합니다. 개인/외국인합계/기관합계 순매수대금을 파싱하여 investor_flow에 저장. 요청 간 0.4초 딜레이.

발견된 버그: 존재하지 않는 함수 호출 기존 코드는 get_market_net_purchases_of_equities_by_date()라는, 설치된 pykrx 버전(1.2.8)에는 존재하지 않는 함수를 호출하고 있었습니다. 매 호출마다 예외가 발생 → except로 조용히 삼켜짐 → 데이터가 전혀 쌓이지 않는 상태였습니다. 실제 존재하는 get_market_trading_value_by_date()로 교체하고, 반환 컬럼명(개인/외국인합계/기관합계)에 맞춰 파싱 로직도 수정했습니다.
추가 필요조건: KRX 로그인 세션 pykrx 1.2.x부터 투자자별 거래실적 API는 data.krx.co.kr 로그인 세션(쿠키)이 있어야 정상 응답합니다. 로그인 정보가 없으면 KRX 서버가 "LOGOUT" 텍스트만 반환하고 pykrx는 이를 빈 DataFrame으로 처리합니다. .env에 KRX_ID/KRX_PW(data.krx.co.kr 무료 회원가입) 설정이 필요합니다.

또한 collector/stock_daily.py, investor_flow.py 둘 다 pykrx를 import하는 시점에 세션이 생성되는데, 기존 코드는 db.connection(= config.load_dotenv())보다 pykrx import가 먼저 실행되어 .env의 KRX 로그인 정보가 반영되지 않는 순서 버그가 있었습니다. 두 파일 모두 pykrx import 전에 load_dotenv()를 명시적으로 호출하도록 수정했습니다.

8. Processor 모듈 processor/

signals.py — Heat Score 계산

대상 날짜의 전 종목에 대해 30일 이동 기준(window) 대비 오늘 값의 비율을 계산하고, 3가지 요소를 결합하여 0~10 스케일의 heat_score를 산출합니다.

구성 요소 및 가중치

요소계산식최대 기여
개인 순매수 비율(individual_flow_ratio - 1.0) × 3.04.0점
신용 급등 비율(credit_surge_ratio - 1.0) × 3.03.0점
거래량 급등 비율(volume_ratio - 1.5) × 2.03.0점

Signal 분류

heat_score < 7.0   → "neutral"  (진입 가능)
7.0 ≤ score < 8.5  → "avoid"   (진입 불가)
score ≥ 8.5        → "sell"    (청산 신호)
발견 및 수정된 버그: numpy float64 삽입 실패 (2026-08-10) numpy 2.0부터 repr(np.float64(x))가 "np.float64(x)" 형태로 바뀌었는데, psycopg2가 이 문자열을 그대로 SQL에 삽입하면서 compute_for_date()의 모든 INSERT가 InvalidSchemaName 에러로 실패하고 있었습니다. 배포 이후 실전 스케줄러가 단 한 번도 정상적으로 신호를 생성한 적이 없었다는 뜻입니다 — contrarian_signals가 비어있으니 진입/청산 후보도, 거래도 발생할 수 없었습니다. flow_r/credit_r/vol_r을 삽입 전 파이썬 네이티브 float()로 캐스팅하도록 수정되었습니다. (이 저장소의 backfill_signals.py는 처음부터 네이티브 float를 사용해 이 버그의 영향을 받지 않았습니다.)

indicators.py — 기술적 지표

SMA, rolling_std, volume_ratio, 52주 위치(pos_52w), 일간 로그 수익률 등을 numpy 배열로 계산합니다. 현재 메인 파이프라인에서 직접 호출되지는 않고 전략 분석용으로 준비되어 있습니다. 모든 지표는 t-1 데이터만 참조하여 look-ahead bias를 방지합니다.

9. Strategy 모듈 strategy/contrarian.py

진입 후보 (get_entry_candidates)

다음 조건을 모두 충족하는 종목만 반환합니다:

  • heat_score < HEAT_AVOID (기본 7.0)
  • signal = 'neutral'
  • positions 테이블에 없는 종목 (미보유)
  • 52주 위치 ≤ 30% (52주 저점 근처)

출력: [{code, close, heat_score, pos52w}, ...] — heat_score 오름차순 정렬

청산 후보 (get_exit_candidates)

보유 포지션 중 아래 조건을 검사합니다 (우선순위 순):

우선순위조건청산 사유
1close_price ≤ stop_px"stop"
2held_days ≥ max_hold_days"expiry"
3heat_score ≥ HEAT_SELL"heat_signal"

10. Agents 모듈 agents/

base.py — Claude API 래퍼

call(agent_name, code, prompt)는 MD5(agent + code + prompt)로 agent_decisions 테이블을 먼저 조회합니다. 캐시 히트 시 API 호출 없이 재사용, 미스 시 Claude API 호출 후 결과를 저장합니다.

Claude 응답 포맷 (파싱 대상)

결정: 매수 | 관망 | 청산
확신: 0~10
이유: 한 문장 근거

오류 처리

API 키 미설정 또는 호출 실패 시 기본값 "관망"을 반환합니다.

gate.py — 합의 게이트

에이전트역할veto하드코딩 규칙
market_state시장 전반 상태Yesfall_pct ≥ 70% → 강제 "청산"
risk포트폴리오 리스크Yesfree_slots = 0 또는 same_sector ≥ 3 → 강제 "관망"

에이전트별 입력 데이터

market_state

전체 종목 중 하락 비율(fall_pct), KODEX 200 20일 수익률(trend_pct). Claude에게 약세장·심리·트렌드 기반 매수/관망/청산 판단을 요청합니다.

risk

paper.py — 모의 매매 운영 중

buy(code, name, signal_date, close_px, heat_score, agents_summary)

  1. positions 수 ≤ SLOTS 확인
  2. stock_daily에서 다음 거래일 시가 조회
  3. 매수 비용 모델 적용: entry_px = next_open × (1 + SLIP) × (1 + FEE)
  4. 손절가 계산: stop_px = entry_px × (1 - STOP_PCT)
  5. positions 삽입, trades 삽입 (side='buy')

sell(code, name, qty, entry_px, close_px, reason)

  1. 매도 비용 모델 적용: fill_px = close_px × (1 - SLIP) × (1 - FEE - TAX)
  2. 수익률 계산: realized_pct = fill_px / entry_px - 1
  3. 원 매수 trade에 exit_reason, realized_pct 업데이트
  4. 매도 trade 삽입, positions에서 삭제

13. Backtester 모듈 backtester/

engine.py — 이벤트 기반 백테스트

run(start, end, ...)는 contrarian_signals를 직접 조회하여 진입→청산 시뮬레이션을 수행합니다.

시뮬레이션 로직:
1. heat < heat_avoid & signal='neutral' 종목 → 다음 거래일 시가로 진입
2. 이후 20일간 매일 확인:
   a. low ≤ stop_px   → 손절 (비관적 fill: stop_px 사용)
   b. heat ≥ heat_sell → 과열 청산 (당일 종가)
   c. days_held ≥ max_hold → 만기 청산 (당일 종가)
3. 비용 모델(cost_model.py) 적용하여 순수익률 계산
발견 및 수정된 버그: 중복 포지션 무한 누적 (2026-08-10) active 딕셔너리가 "이미 보유 중인 종목 스킵" 용도로 선언만 되어 있고 실제로 갱신(active[code]=...)되지 않아, 동일 종목에 heat 조건을 만족하는 날마다 매일 새 포지션이 중복으로 열리는 버그였습니다. 수정 전 2022~2024 백테스트 거래 수가 848,416건(비현실적)이었는데, 수정 후 64,403건으로 정상화됐습니다. 실전 매매(executor/paper.py)는 positions 테이블 PK 제약 덕분에 이 버그의 영향을 받지 않았습니다 — 백테스터 전용 버그였습니다.

16. 핵심 비즈니스 로직

Heat Score 공식

heat_score = clamp(
    (flow_ratio - 1.0) * 3.0      # 개인 과열 기여 [0, 4]
  + (credit_ratio - 1.0) * 3.0    # 신용 과열 기여 [0, 3]
  + (vol_ratio - 1.5) * 2.0,      # 거래량 급등 기여 [0, 3]
  0, 10
)

진입 조건 체크리스트

  1. heat_score < 7.0
  2. signal = 'neutral'
  3. 미보유 종목
  4. 52주 위치 ≤ 30%
  5. market_state 에이전트 → 매수 승인
  6. risk 에이전트 → 매수 승인
  7. retail_flow + credit_heat 모두 "매수" 투표

청산 조건 (우선순위)

  1. 손절: close ≤ entry × (1 - 0.07)
  2. 만기: held_days ≥ 20
  3. 과열 청산: heat_score ≥ 8.5

비용 모델

# 매수 실효가
entry_px = market_px × 1.0020 × 1.000150   # +0.215%

# 매도 실효가
exit_px  = market_px × 0.9980 × 0.999650   # -0.235%  (수수료 0.015% + 세금 0.20%)

# 순수익률
net_return = exit_px / entry_px - 1
Look-Ahead Bias 방지 모든 지표는 t-1 데이터 기준으로 계산됩니다. 진입은 신호 발생 다음 거래일 시가 기준으로 실행됩니다.
